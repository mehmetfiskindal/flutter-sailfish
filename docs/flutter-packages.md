## What this means

- **Works as is (3):** `shared_preferences`, `path_provider` (verified on the device) and `cross_file`. `flutter-sailfish` registers their pure Dart Linux implementations.
- **Blocked by a native GTK part (3):** `url_launcher`, `file_selector`, and `image_picker` (its Linux implementation is pure Dart but calls `file_selector`). The generated registration still registers the Linux class, and calls fail at run time (the build prints a warning). They need a Sailfish implementation of the same platform interface (`url_launcher_platform_interface`, `file_selector_platform_interface`).
- **No Linux implementation (11):** `camera`, `video_player`, `webview_flutter`, `local_auth`, `google_maps_flutter`, `google_sign_in`, `in_app_purchase`, `quick_actions`, `pointer_interceptor`, and `espresso` (Android test helper) and `interactive_media_ads`. On Sailfish they throw `MissingPluginException` until an implementation exists.
- **Plain packages (about ten that matter; the rest is tooling):** `go_router`, `animations`, `rfw`, `vector_graphics`, `google_fonts`, `two_dimensional_scrollables` and others declare no platform code and should simply work. Not tested here, except that the Flutter framework itself runs. `google_fonts` downloads fonts over the network, so it needs the `Internet` permission.

A federated plugin lets one package supply the implementation for another: a `url_launcher_sailfish` package that implements `UrlLauncherPlatform` and registers itself would make `url_launcher` work unchanged for app code. Most Sailfish services are reachable over D-Bus, which works from pure Dart (see `engine-build.md`), so many of these implementations need no native code.

## Suggested order

1. **Override rule in `flutter-sailfish`:** when a package with a `sailfish` entry declares `implements: <app-facing package>`, the Linux implementations of that package are not registered (otherwise both would register and the last one wins).
2. **`url_launcher_sailfish`** (pure Dart, D-Bus): small, visible, and exercises the override rule.
3. **`local_auth`** (fingerprint over D-Bus, `FingerprintSensor` permission) if the device has a sensor.
4. **`file_selector` and `image_picker`:** Sailfish's pickers are Silica QML components, which a Qt/C++ runner does not have; needs a design decision (embed QML, or a different mechanism).
5. **`camera`, `video_player`, `webview_flutter`:** large (GStreamer or Qt Multimedia with engine textures; Gecko for web views). Plan separately.
6. Google services packages (`google_sign_in`, `in_app_purchase`, `google_maps_flutter`) depend on Google Play services and are out of reach; alternatives (OAuth in the browser) would be other packages.
