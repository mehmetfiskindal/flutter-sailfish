# flutter-sailfish

An unofficial, experimental port that runs Flutter apps on Sailfish OS.

It is a small Qt/OpenGL ES host ("runner") for the **unmodified** Flutter engine, plus a build wrapper
(`flutter-sailfish`) that handles plugins, native plugin code, Sailjail permissions and RPM packaging,
and notes on how everything is built. It is not affiliated with or endorsed by Google, the Flutter team
or Jolla.

## Status

Proof of concept. A Flutter example app runs from the app grid, in release (AOT) mode, inside the
Sailjail sandbox, on one device.

Tested on: Redmi Note 8 (`aarch64`), Sailfish OS 5.1.0.11, Flutter 3.47.8
(engine `cf636b1dfb818dd6a3ff16e390e93b1a036969c8`). Do not assume it works on your device; reports
are welcome.

| Area | State |
|---|---|
| Rendering (OpenGL ES, Wayland through Qt), touch input | Works |
| Release (AOT) mode | Works; the engine is built from source |
| On-screen keyboard and text input | Works: typing, backspace, enter, predictive text selection |
| App lifecycle (`resumed`, `inactive`, `hidden`, `paused`) | Works |
| Clipboard, `SystemNavigator.pop` | Implemented, lightly tested |
| RPM packaging, launching from the app grid under Sailjail | Works |
| Pure Dart Linux plugins (`shared_preferences`, `path_provider`) | Work; registration is generated by `flutter-sailfish` |
| D-Bus from Dart (`dbus` package): session and system bus, battery level and charger state through `mce` | Works (keep one connection per bus open) |
| Native C++ plugins (Flutter's C++ client wrapper: `MethodChannel`, `EventChannel`, `StandardMethodCodec`) | Work, verified with the echo example plugin |
| Native plugin code built and packaged by `flutter-sailfish` | Works |
| Sailjail permissions declared in plugin/app pubspecs and written to the desktop entry | Works (verified with `Internet`: network blocked without it, allowed with it) |
| Keyboard avoiding a covered field, hardware keyboard, selection handles, context menu | Not verified |
| Accessibility | Not implemented |
| Ready-made Sailfish plugins (camera, location, notifications, ...) | None yet |
| `armv7hl`, `i486`, other devices, other Sailfish versions | Not tried |
| Harbour store compliance | No |
| Debug (JIT) mode | Worked early on with Google's prebuilt embedder; not part of the current scripts |

## How it works

- The engine is the stock Flutter engine for `linux-arm64`, built from the pinned Flutter commit with
  no patches (`engine/flutter_engine.lock`, `scripts/build-engine.sh`).
- `embedder/src/main.cpp` is the runner. It uses Qt 5 (as shipped by Sailfish) for the window, the
  OpenGL ES context, touch events and the Maliit input method, and talks to the engine through the C
  embedder API. A custom **platform task runner** is required; without it no platform channel message
  arrives.
- Apps are compiled ahead of time with the engine's own `gen_snapshot` and shipped as `libapp.so`
  plus `flutter_assets`.
- Plugins are found through their `pubspec.yaml` (`sailfish` platform, or `linux` for pure Dart
  implementations). A `sailfish` entry can carry C++ sources (`nativeSources`) and Sailjail
  permissions (`sailjailPermissions`). See `docs/engine-build.md` for the details.
- Under Sailjail the launcher must be an ELF binary and only the app's own `/usr/share/<name>/` is
  visible, so the app package installs a copy of the runner as `/usr/bin/<name>`, bundles
  `icudtl.dat` next to the app, and the runner points the XDG directories at the places Sailjail lets
  an app write to.

## Repository layout

| Path | Purpose |
|---|---|
| `embedder/` | The Qt runner (`src/main.cpp`, qmake project), the plugin interface header (`include/`) and vendored Flutter code (`third_party/`) |
| `scripts/flutter-sailfish.ps1` | The wrapper: `plugins`, `native`, `permissions`, `build`, `runner`, `package` |
| `scripts/sailfish_plugins.dart` | Reads plugin pubspecs, writes the app's entry point with plugin registration |
| `scripts/build-aot-app.ps1` | The AOT app build (called by `flutter-sailfish build`) |
| `scripts/build-engine.sh`, `export-engine.ps1` | Build the engine in a container; collect its outputs |
| `scripts/build-runner.sh`, `build-native-plugin.sh`, `build-rpm.sh` | Run inside the Sailfish SDK build engine |
| `packaging/` | RPM specs, desktop entry template, icon |
| `examples/counter/`, `examples/echo_plugin/` | Example app and example plugin with native code |
| `engine/flutter_engine.lock` | Pinned Flutter and engine versions |
| `docs/building.md` | How to build, step by step |
| `docs/engine-build.md` | Notes and findings from the work: environment, lessons learned |

Not in the repository: the Flutter engine sources and every build output.

## Building

See [`docs/building.md`](docs/building.md). In short:

```powershell
# once per Flutter version: build the engine in a container (docs/building.md, step 1)
.\scripts\export-engine.ps1
.\scripts\flutter-sailfish.ps1 runner
.\scripts\flutter-sailfish.ps1 build -App examples\counter
.\scripts\flutter-sailfish.ps1 package
```

The scripts were written for Windows with Docker Desktop and the Sailfish SDK; expect to adapt paths
and tools elsewhere.

## Known caveats

- Every Flutter release needs a matching engine rebuild.
- The runner prints a few diagnostics to stderr; set `FLUTTER_SAILFISH_VERBOSE=1` for per-message logging.
- The example package is called `harbour-flutter-counter` only because it was the first name used. The
  `harbour-` prefix is meant for apps accepted into the Harbour store, so rename it for your own work.
- The desktop entry only has the Sailjail permissions that plugins or the app ask for in their
  pubspecs (none by default, so no network).
- `scripts/build-engine.sh` has not been run from an empty container; it collects commands that were run by hand.
